# 1. 目的

本規則は、同じVersion Scopeと証拠を与えられた複数コーダーが、21概念次元について可能な限り同じコードへ到達するための操作規則である。

コード値を埋めること自体を目的にしない。証拠が不足する場合は `U`、構造上適用できない場合は `NA`、同一Scope内で競合する場合は `C` を使用する。

---

# 2. 不変条件

1. **1伝承エントリ = 1行。** 人物・作用・媒体が複数でも行を増やさない。
2. Family内で世界のルールが変わる安定異伝のみ別Entry候補。
3. Parentは入力しない。`Parent=f(Child)` として自動導出する。
4. H3のPrimaryは `D/I` 時に exactly 1。
5. Secondaryは0–2、順不同。保存時のみcode ID順にcanonicalize。
6. `U/NA/C` はコード値ではなくDimension Status。
7. 研究者が真偽を知っていることと、伝承が何を主張するかを分離する。

---

# 3. 証拠ロール

| Evidence role | 用途 | 例 |
|---|---|---|
| `C` Content | 伝承内容、条件、作用、帰結、時間構造 | 原投稿、採録本文、同時代記事による内容引用 |
| `H` History | 成立・流通年代、媒体、変容史 | 同時代報道、媒体史、初出検証、採集史 |
| `X` External effect | 現実社会で実際に起きた効果 | 買い占め、暴力、削除行動、制度対応 |
| `A` Anchor | 実在地・制度・史実との接続 | 公的記録、公式ガイドライン、史料 |

同一資料が複数roleを持ってよい。

**証拠優先順位**

1. 原投稿・同時代一次記録・公式文書
2. 原著論文・民俗採録・同時代報道の再掲
3. 高品質な書誌・研究書・専門家による歴史整理
4. 信頼できる二次資料
5. その他の解説

下位資料しかない場合はStatusを `I` とし、根拠メモを残す。

---

# 4. Dimension Status

- `D` Direct — 典拠に直接明示
- `I` Inferred — 定義と証拠から合理的に推定
- `U` Unknown — 資料不足
- `NA` Not applicable — 構造上非該当
- `C` Conflict — 同一Version Scope内で競合

`U` を「最もありそうな値」で埋めてはならない。

---

# 5. コーディング順序

原則として次の順に行う。

1. Entry_ID / Family_ID / Entry_Type / Version_Scopeを固定
2. D07 意味形成対象
3. D08 意味形成契機
4. D09 意味付与操作
5. D10 因果源存在論
6. D11 発動・接触条件
7. D12 作用対象
8. D13 作用機構
9. D14 帰結極性
10. D15 帰結領域
11. D16 因果時間構造
12. D17 回避・制御
13. D18 作用レイヤー
14. D01–D06 来歴・提示
15. D19–D21 社会的分布・現実アンカー

Macro Categoryや旧14軸コードから新コードを逆算してはならない。

## 5.1. Version Scopeの既定選択

Version Scopeが別途指定されていない場合は、次の順で固定する。

1. 原投稿・同時代記録等により**成立時のまとまった伝承形**を直接確認できる場合、その最古のまとまりを既定Scopeとする。
2. 後代要素は、同一の意味形成核を保ち、かつ分析に不可欠であることを明示できる場合だけ含める。
3. 後代の創作翻案、世界のルールを変える安定異伝、因果源・発動条件・作用・帰結を追加変更する派生は既定Scopeから除外する。
4. 成立時のまとまった形を直接確認できない場合は、複数資料で確認できる**最も早い安定した共有核**までScopeを狭める。競合する異伝を無理に統合しない。

Scopeを広くすること自体を目的にしない。後代要素を混ぜた方が有名・豊富になる場合でも、成立時の構造を上書きしない。

# 6. H1 / H3 共通規則

## 6.1. Primary

その次元について、Entryの意味形成構造を最も強く規定するChild。

## 6.2. Secondary

Primaryだけでは失われる、独立した追加構造。背景・舞台・結果の言い換えはSecondaryにしない。

## 6.3. Parent

Childからコードブック表で一意に導出する。コーダーはParentを判断しない。

## 6.4. 近接Childのtie-break

同一Evidenceから複数Childが候補になる場合、次の順でPrimaryを決める。

1. その次元の**中心質問へ最も直接答える**Child。
2. Version Scope内の**より強い直接証拠**で支えられるChild。
3. 背景・結果・後代解釈ではなく、Scoped Entryの意味形成構造に**不可欠な役割**を表すChild。
4. 追加の未確認前提を必要としない、**より保守的なChild**。
5. もう一方も独立した追加構造として必要ならSecondaryへ置く。

それでも一意に決められない場合、恣意的にPrimaryを選ばず、該当次元の個別規則を再確認する。規則側でも解消できない分類体系上の曖昧さは、コードブック改訂候補として扱う。

---

# 7. D01 — 生成年代

最古確認層と推定起源を混同しない。証拠が「遅くとも1994年」までしか示さない場合、1994年を断定的な生成年にしない。年代レンジへ安全に写像できなければU。

---

# 8. D02 — 最古確認流通媒体

## 8.1. 中心質問

> 現在の証拠で、伝承が実際に人から人へ流通したことを最も古く確認できる媒体は何か。

## 8.2. 最重要規則

- 「古い伝説だから口承」「ネット発祥でないから口コミ」は禁止。
- `Entry_Type=FOAF` はD03の流通推定には使えるが、D02の最古媒体の証拠には単独では不十分。
- 後代の事典・研究書は、掲載されているだけでは最古媒体にしない。

## 8.3. 判定フロー

1. 原投稿・原メール・原手紙・同時代記事が発信媒体か → その媒体をD。
2. 後代資料が「学校で聞いた」「子どもの噂」「口コミ」等を明示するか → 対応するORLをIまたはD。
3. 史料が複数あり最古確認媒体が特定できるか → 最古を採る。
4. それ以外 → U。

## 8.4. 例

- 口裂け女：1978年末の子どもの噂が後代専門家整理で明示 → `D02.ORL.PEER_ORAL` I/D。
- きさらぎ駅：2004年2ch実況 → `D02.WEB.FORUM` D。
- JDBGMGR.EXE：チェーンメール → `D02.EDG.EMAIL` D。
- 水からの伝言：1999年写真集が主張の発信源 → `D02.PRT.BOOK` D。
- 初出不明のFOAFを「友人・仲間内伝承」と推定 → **禁止、U**。

---

# 9. D03 — 確認流通媒体ポートフォリオ（Version Scope）

## 9.1. 中心質問

> 今回コードするVersion Scopeで、伝承が受容者へ流通したことを確認できる媒体は何か。

「現在」「主要」という語は使用しない。

## 9.2. Primary規則

複数媒体がある場合、次の順でPrimaryを決める。

1. Version Scopeの成立に構造的に不可欠な媒体
2. 典拠が主な拡散回路として明示する媒体
3. Version Scope内で最も早く直接確認される媒体

残りをSecondary 0–2とする。

## 9.3. Include

- 子ども同士の口コミ
- FOAFとしての対人流通
- チェーンレター・メール
- 原掲示板・SNS
- 同時代新聞・雑誌が伝承を広く再提示し、流通史の一部になったことが確認できる場合
- 書籍・テレビ等が伝承を実際に再流通させたと資料が示す場合

## 9.4. Exclude

- 研究DBに収録されているだけ
- 現在Google検索で見つかるだけ
- ファクトチェック記事が存在するだけ
- 参考文献として書籍が使われただけ

## 9.5. D02との関係

D03 PrimaryがD02と同じでもよい。これは媒体継続を意味する。媒体移行が確認される場合、D04と併せて解釈する。

---

# 10. D04 — 生成・変容パターン

変容が確認できない場合、資料不足を `単発固定` にしない。変化を示すH証拠がなければU。

---

# 11. D05 — 提示形式

研究者による要約形式ではなく、伝承が受容者へ提示される形式をコードする。原実況、FOAF、命題、警告、俗信規則等。

---

# 12. D06 — 真実性提示

研究者の真偽判定ではなく、伝承が要求する認識論的スタンスをコードする。

---

# 13. D07 — 意味形成対象

必ず「この伝承がなければ何が説明されないまま残るか」を一文で書いてからChildを選ぶ。結果や因果源を対象として誤コードしない。

---

# 14. D08 — 意味形成契機

意味形成を開始させる証拠・徴候・パターンをコードする。発動条件D11と分ける。

---

# 15. D09 — 意味付与操作

伝承が不可解さを理解可能にするために行う認知操作をコードする。例：主体帰属、原因帰属、カテゴリー化、意図帰属、規則化、予兆化。

近接する `MYSTERY_LABEL` と `DELIBERATE_NONRESOLUTION` は次で分ける。

- `MYSTERY_LABEL`: 原因を確定せず、名称・怪異・謎として安定して把握可能にする。単に未解決である場合はこちらを優先する。
- `DELIBERATE_NONRESOLUTION`: 複数説を**意図的に併置・維持し、結論を閉じないこと自体が提示戦略**であるEvidenceがある場合に用いる。

「結局わからない」「複数説が出た」だけで `DELIBERATE_NONRESOLUTION` にしない。

---

# 16. D10 — 因果源存在論

何が因果源として置かれるか。体験報告の存在と超自然原因の実在を分離する。原因主体を立てない異常体験は現象・体験系Childを使う。

明示的な主体がなくても、Version Scope内の異常が一貫して**場所・経路・接続関係そのもの**に依存して成立する場合、対応する場所・時空系Childを `I` で選べる。単に主体が不明という理由だけで `U` にしない。

`ALTERNATE_WORLD` 等の強い存在論は、Scope内で別世界・異界等が原因層として明示または安定して確定される場合に限る。受容者の推測や後代解釈だけでは付与しない。

---

# 17. D11 — 発動・接触条件

伝承の因果系へ入る条件。単に「読者がこの話を読む」ことを、伝承内容上の発動条件でない限りコードしない。

日常的な行為が異常発生時の物理的文脈にすぎず、**その行為をすれば再現的に発動する**という規則がない場合は、受動発生・偶然遭遇系をPrimaryとし、その行為は構造上必要ならSecondaryとする。

反対に「特定の列車へ乗る」「特定地点へ入る」こと自体が再現可能な発動規則として提示される場合は、対応する行為・移動条件をPrimaryとする。

---

# 18. D12 — 作用対象

D12は、**D13で記述する主作用が直接向けられる対象**をコードする。物語上の主人公、最終的な利益・被害の受け手、意味形成上目立つ人物を自動的にPrimaryとしてはならない。

判定は次の順で行う。

1. D13のPrimaryとなる主作用を一文で特定する。
2. その主作用を直接受ける人物・物・場所・制度等をD12 Primaryとする。
3. 同じ因果列で、別の対象にも独立した作用が直接及ぶことがVersion Scope内で確認できる場合だけSecondary候補とする。
4. 直接作用を媒介して最終的に利益・被害・知識変化等を受ける主体は、それだけを理由にD12 Primaryへ置かない。その変化はD15で表現する。

したがって、物体操作が主作用であり、その物体の変化を通じて人物が情報・利益・危険を受ける場合、物体がD12 Primaryとなる。人物側にも別個の直接作用が確認できる場合に限り、人物をSecondary候補とする。

D12・D13・D15は、原則として次の因果列として読めなければならない。

```text
D12: 何に作用するか
→ D13: その対象へ何をするか
→ D15: その結果、最終的に何の領域が変わるか
```

この三者が接続しない場合は、D12の対象選択、D13の主作用、D15の帰結領域のいずれかを再確認する。

---

# 19. D13 — 作用機構

「何をするか」をコードし、帰結と分ける。資料不足を顕現・観測にしない。

---

# 20. D14 — 帰結極性

主帰結の正負中立をコード。複数が同等ならMixed。研究者評価ではなく伝承内／伝播現実の結果に基づく。

---

# 21. D15 — 帰結領域

最終的に何が変わるか。作用機構との重複を避ける。Primary 1、Secondary 0–2。

Version Scopeの終端で身体被害・死亡・失踪等が**確認されず**、所在・帰還・真相等が未確定のまま残ること自体が安定した終端状態である場合は、`KNW.UNCERTAINTY_PRESERVED` をPrimary候補とする。「投稿停止」「その後不明」を死亡・失踪へ読み替えない。

---

# 22. D16 — 因果時間構造

## 22.1. 中心質問

> 発動条件・原因成立から主作用／主帰結までの関係は、時間上どのように編成されているか。

## 22.2. v2の重要変更

非物語型・静的命題をUにしない。時間進行を必要としない関係は `STA` として明示する。

## 22.3. 判定フロー

1. 属性・同一性・対応・制度規則等で、時間順序が意味上不要か → `STA`
2. 一つの連続した出来事の中で完結するか → `EVT`
3. 待ち時間・期限・潜伏が意味上重要か → `DLY`
4. 徐々に悪化・進展するか → `PRG`
5. 一度収束した後に再び起こるか → `REC`
6. 作用関係が切れず持続するか → `CON`
7. A→B→C、世代間など対象を移るか → `TRN`
8. 動的時間構造が重要だが資料が足りない → U

## 22.4. STAの例

- 血液型性格判断：「血液型X ↔ 性格Y」→ `STATIC_ASSOCIATION`
- ひよこ鑑定士高給説：「職業Xは高給」→ `STATIC_ATTRIBUTE`
- 事故物件俗説：「一度他人を住ませれば告知義務が消える」→ `STATIC_RULE`
- 樹海で方位磁針が狂う → `STATIC_ASSOCIATION`

## 22.5. EVTの例

- ベッドの下の男：一晩の出来事 → `SINGLE_EPISODE`
- 臓器を抜かれるFOAF：誘引→昏睡→摘出→覚醒 → `SEQUENTIAL_EPISODE`
- きさらぎ駅：一晩の実況内で段階的に異常が進む → `SEQUENTIAL_EPISODE`

## 22.6. 注意

伝承自体が数十年流通していることはD16ではない。D01/D04の問題である。

---

# 23. D17 — 回避・制御

伝承が提示する制御可能性。資料に対処法がないから「不可避」としない。不可避には明示証拠が必要。

---

# 24. D18 — 作用レイヤー

- L1 伝承内因果層
- L2 受容者層
- L3 社会現実層

L3はX証拠が必要。噂なら社会効果が起きそう、という推測だけでは付与しない。

---

# 25. D19 — 流通範囲

媒体D03と分ける。「どの媒体で」ではなく「どの社会範囲まで」流通しているか。

---

# 26. D20 — 特権情報保持者

噂を知っている人ではなく、真相・追加情報・回避情報を偏って保持する主体。

`NO_ONE_KNOWS` は強いコードであり、単に「資料に情報保持者が書かれていない」場合には使わず `U` とする。

`NO_ONE_KNOWS` を `I` で用いてよいのは、Version Scope内で、主人公・家族・警察・専門家・共同体・参加者等の**もっともらしい情報保持者／権威が実際に探索・照会・提示されるにもかかわらず、誰にも真相・追加情報・有効な制御情報が成立しない構造**が確認できる場合である。

この `I` は「宇宙内の全存在が知らない」という形而上学的断定ではなく、**当該Version Scopeが特権情報保持者を成立させていない**という情報構造上の推論を意味する。特定の隠れた保持者・専門家・内部者が示唆される場合は、対応Childまたは `U` を検討する。

---

# 27. D21 — 現実アンカー

典拠が実在することと、伝承内容が現実へ接続することを分離する。実在制度・史実が主張成立に必要な場合のみ高得点。

---

# 28. 第2パイロットの検証項目

特にD02/D03/D16について以下を比較する。

- U率
- Parent使用数
- H_norm
- K_eff
- 最大Parent占有率
- D/I比率
- v1→v2で変更されたEntry数

**解釈**

- D02はU率低下を唯一の目標としない。**誤った口承推定を減らすこと**を優先する。
- D03は「現行・主要」を捨てたことでU率が大きく下がるかを見る。
- D16はSTA/EVT導入で、非物語型と単一エピソード型の疑似Uが減るかを見る。
