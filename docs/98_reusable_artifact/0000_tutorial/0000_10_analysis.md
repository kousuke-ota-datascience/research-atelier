# 2. 分析概念次元

各次元は、単にコード値を記録するだけでなく、**当該伝承においてその次元が具体的にどのように現れているか**まで自然言語で記述する。

各次元の記載順序は、原則として以下とする。

1. コード値（Primary / Parent / Secondary / Status等、その次元で必要な値）
2. 判定根拠
3. **この伝承における現れ方**
4. 必要に応じた境界・留保

「この伝承における現れ方」では、コード定義の言い換えではなく、人物・場所・出来事・主張・条件・帰結等を用いて、その伝承内で実際に何が起きる／何が主張されるため当該コードになるのかを書く。後からコード表だけを見なくても、伝承固有の展開と分析概念の対応を再構成できる密度を持たせる。

`Status = U` の場合も空欄にせず、「何が確認できないため、どこまで言えないのか」を記述する。`Status = NA` の場合は、「なぜ当該伝承構造ではその次元が成立しないのか」を記述する。`Status = C` の場合は、競合する伝承形・資料・解釈を明示する。
